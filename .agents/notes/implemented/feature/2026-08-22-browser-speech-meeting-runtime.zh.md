# Agent Note: 浏览器语音会议运行时

Status: implemented

[English](2026-08-22-browser-speech-meeting-runtime.md) | 中文

## Problem

目标 Windows 主机上的纯 CPU FunASR 处理会议音频的速度低于实时速度。长时间会议中的延迟持续增加，子进程退出还可能让 Host 报告一个实际已停止采音的会议。

## Decision

会议面板使用 Web Speech API 和 MediaRecorder 采集浏览器麦克风。每个短时语音识别实例在本地显示临时文本，并只将确定转写增量提交给 Host；面板保持挂载时，普通结束、无语音、中止和临时网络错误都会新建识别实例。权限、服务、语言或采集终止错误会停止本地采集并显示错误。

Host 负责会议标识、有序转写持久化、增量摘要定时、音频保存和最终纪要生成。转写帧携带单调递增序号，Host 忽略重复帧。MediaRecorder 每五分钟产生一个音频分片；有序分片保存为 audio-NNNN.webm 或 audio-NNNN.ogg，账本记录已提交数量，因此恢复录音不会覆盖已有分片。

Host 在确认每条确定转写前完成持久化。每个成功的增量摘要独立写入 summary-NNNN.md。最终生成读取完整持久转写和全部已提交摘要，不删除中间文件。浏览器刷新会停止采集，但 Host 账本仍保持录音状态；面板提供恢复操作，并从已有转写和音频编号继续。

## Alternatives considered

**保留 CPU FunASR 实时转写。** 实测进程在一次短会议中累计落后三分钟以上，无法在目标 CPU 上满足长会议的低延迟展示。

**使用 Web Speech 但不保留音频。** 这种方案降低延迟，但浏览器服务或网络故障期间的语音无法恢复。五分钟 MediaRecorder 分片保留后续恢复所需的音频来源。

**只生成最终纪要。** 最终生成失败时，长会议可能失去全部已整理信息。独立增量摘要文件提供持久检查点，并作为可重试最终生成的可选输入。

## Consequences

实时识别使用浏览器服务延迟，不再承受本地模型积压，也不再启动 Python 或 FunASR。识别依赖浏览器支持、麦克风权限、保持会议面板打开以及浏览器语音服务可用。自动重建识别实例能缓解普通断线，但浏览器或操作系统挂起页面时无法继续采集。已上传音频保留完整的五分钟分片；离线自动补转写仍为后续工作。
